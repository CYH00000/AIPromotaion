# 抖音与小红书评论采集管理系统

本项目用于个人学习与非商业研究，基于 NanmiCoder/MediaCrawler 上游二次开发，支持抖音和小红书的关键词/链接采集、评论筛选、定时任务、结果检索与 CSV/Excel 导出。

## 当前状态

本地 MVP 已实现管理员会话、任务 CRUD/停用、手动/间隔/Cron 调度、串行运行队列、关键词排序与发布时间范围、关键词筛选、AI 语义规则草稿/预览/批准、评论去重与运行快照、评论搜索及 CSV/XLSX 导出。采集任务通过 MediaCrawler CLI 执行；平台真实登录态和账号流程沿用上游。

本地 MVP 同时包含抖音/小红书扫码登录、账号配置状态和解绑，以及任务运行阶段、暂存数量、最近活动、日志和停止操作的运行时观测；管理界面与运行状态均为中文。

尚未纳入 MVP：云端 HTTPS 反向代理与部署包、真实平台端到端验收、Cookie 粘贴登录、二维码内嵌网页、多账号管理、按平台并行和边采集边入库。当前版本不应直接暴露到公网。

已选采集底座：NanmiCoder/MediaCrawler，设计基线 SHA `68d9ef1c1da22eab75940dfd7cec259907006538`。采集核心采用非商业学习许可证；上游 WebUI 使用 GPL-3.0。详见 [许可证与来源清单](../LICENSES.md)。

## 设计基线摘要

- 抖音和小红书各配置一个授权账号。
- 每个采集任务选择一个平台及一种来源：关键词或指定内容链接。
- 关键词任务可选择综合/最新/最多点赞排序，以及不限/一天/一周/半年发布时间；指定链接模式按链接采集。
- 任务支持手动执行、固定间隔及 Cron 计划。
- 评论主记录按平台评论 ID 去重；每次运行保存观察快照。
- 作者只保留平台用户 ID、昵称和主页链接，主页资料只为命中评论补充。
- AI 规则由自然语言生成，需先预览并由用户批准。
- 批准的 AI 规则版本绑定到任务；每次运行固定规则快照。语义判断只发送筛选后的评论文本，不发送作者字段。
- 模型服务对超时、限流、5xx 和网络错误最多重试 3 次；单批最终失败只影响该批，其余批次继续判断。失败评论不作为命中保存，运行记录失败数量和错误类型。
- 平台账号状态来自本机浏览器配置目录；不新增平台账号数据库表，状态只表示本地配置存在，真实有效性由运行时检查确认。
- 运行记录保存阶段、暂存数量、最近活动时间和进度；运行中超过阈值没有活动时显示「无活动」，但不会自动杀进程。
- 云端采用 PostgreSQL、单管理员登录、HTTPS 和单实例采集 Worker。

## 本地运行边界

- 本地服务绑定 `127.0.0.1:8080`，PostgreSQL 绑定 `127.0.0.1:5433`。
- XHS 输入链接保存时会丢弃临时 `xsec_token` 参数；定时任务运行时由上游采集器使用规范内容链接和本地登录态访问。
- 每次运行的 JSONL 暂存仅用于筛选/入库，完成后删除；业务数据库只保留命中过滤的评论和白名单作者字段。
- 服务中断时尚未完成入库的暂存目录移动到 `data/recovered_runs/<run_id>/` 保留；运行标记为 interrupted，不自动重新执行 AI 入库。
- 云模型由服务端 `.env` 配置；API 密钥只保存在被 Git 忽略的本地 `.env` 或部署密钥中，API 不回传密钥。
- 本地初始管理员密码由启动前写入 `.env`，不得提交。
