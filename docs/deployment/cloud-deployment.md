# 云部署与运维说明

> 本文是目标部署设计，不代表当前 MVP 已达到公网部署条件。当前仅支持本机回环地址开发验证。

## 目标拓扑

单台 Linux 云服务器运行 Compose 服务：HTTPS 反向代理、React/Vite + FastAPI Web/API、单实例采集 Worker、PostgreSQL 18 系列。浏览器资料和数据库数据分别使用持久卷。公网只允许 HTTPS 管理入口。

## 配置要求

部署环境通过秘密管理器或服务器环境变量提供：

- 管理员密码与会话/CSRF 配置。
- PostgreSQL 用户/密码和数据库名。
- 抖音与小红书登录凭据或持久浏览器会话配置。
- AI 服务 Base URL、模型名和 API Key。
- 公开站点域名、可信反向代理地址、时区和采集上限。

真实密钥不写入仓库、镜像、Compose YAML、日志、截图或聊天。应用接口只返回密钥是否已配置，不返回秘密内容。

## 网络边界

- 主机防火墙只开放 443；HTTP 端口仅用于跳转到 HTTPS（若反向代理配置需要）。
- PostgreSQL、FastAPI 内部端口、Worker API、Playwright/CDP 端口绑定私网或容器内部网络。
- 禁用公开注册；生产加固需要 TLS、密码哈希、Secure/HttpOnly/SameSite 会话、CSRF 防护和登录限速。MVP 当前从本机 `.env` 读取管理员密码，公网部署前必须替换为符合该要求的秘密管理方案。
- 生产 API 文档需要认证；健康探针只返回最少状态，不返回数据库连接、Cookie 状态值或环境变量。
- Worker 运行用户使用最小权限；平台浏览器配置目录仅挂载给 Worker。
- 模型地址仅允许 HTTPS，并阻止 loopback、私网和云元数据地址；应用不跟随到受限网络的重定向。

## 上线步骤

1. 选择受支持的 Linux 主机、配置域名 DNS 和 HTTPS 证书。
2. 在云服务器建立私有部署目录，使用经审查的 release tag 或 commit。
3. 通过秘密管理器注入生产配置，先验证变量完整性，不回显值。
4. 执行数据库迁移；新版本升级前创建加密备份。
5. 启动 PostgreSQL 与 Web/API，检查 ready 探针和单管理员登录。
6. 启动单实例调度器，确认抖音和小红书运行时心跳、计划恢复、账号会话和排队状态可用。
7. 从公网检查 HTTPS 登录、业务 API 鉴权和 CSV/Excel 导出。
8. 用户手动触发小范围真实平台任务，检查遇到验证/限流时是否停止。
9. 记录部署 commit、迁移版本、备份标识和回滚目标。

## 备份与恢复

- 每日加密 PostgreSQL 逻辑备份；备份目录不挂载到公开 Web 根目录。
- 浏览器登录资料单独加密备份并限制访问；其访问权限至少与数据库备份同等严格。
- 不自动删除主数据库采集数据；备份保留周期由部署者配置。
- 恢复前暂停 Worker；在隔离数据库验证备份，再切换生产数据目录并检查外键、任务、评论和快照数量。
- 恢复后重新检查平台登录态；不要把 Cookie/令牌从日志或备份检查输出中打印出来。

## 监控与故障处置

- Web/API：存活探针、就绪探针、登录失败率和 5xx 计数。
- Worker：最近心跳、队列长度、运行任务状态、最近失败类型和调度器恢复状态。
- 数据库：磁盘占用、连接数、备份成功时间、最近一次恢复演练。
- 网络/平台错误：登录失效、挑战、限流、封禁单独分类；暂停该账号后续采集并要求人工检查。不得自动更换代理、账号或伪装访问。
- 模型错误：超时、429、无效响应保留评论与运行状态，可手动重试；不把失败当作通过。

## 回滚

应用回滚到上一个经过验收的镜像/commit。若数据库迁移向后不兼容，先按迁移文档还原备份；Worker 停止后再回滚 Web/API，避免旧代码读写新结构。回滚后核验管理员登录、任务列表和最近快照。

当前文档是部署设计，不代表项目已有 Docker 镜像或可直接运行的云部署包。
