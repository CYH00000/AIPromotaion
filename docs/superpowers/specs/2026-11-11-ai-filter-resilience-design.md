# 智能筛选重试与批次隔离设计规格

- 日期：2026-11-11
- 状态：已确认；待实施
- 范围：智能语义筛选的超时、重试、批次失败隔离和错误可见性

## 1. 问题与证据

2026-11-11 的一次运行产生 1688 条评论、17 条无效、100 条语义过滤、1571 条语义失败、0 条命中。

实测 `deepseek-v4-pro` 单批 20 条评论约需 24 秒，推理 token 约 1600–2100；`.env` 的 `AI_FILTER_TIMEOUT_SECONDS` 为 30。当前 `ingest_staging_directory` 在任意一批出错时把剩余全部候选标记为 `semantic_failed` 并 `break`，一次临时失败因此被放大成 1571 条失败。

## 2. 目标

- 将默认语义请求超时提高到 90 秒；
- 对超时、429、5xx 和网络错误最多重试 3 次，指数退避；
- 某一批最终失败时只把该批（最多 20 条）计为失败，继续处理后续批次；
- 在运行计数中记录安全错误码和安全摘要，界面可见；
- 不改变“语义失败评论不入库”的既有业务规则。

## 3. 非目标

- 边采集边入库；
- 更换模型供应商或自动切换模型；
- 把原始评论、密钥或完整请求头发送给日志；
- 对配置错误、无效 JSON 等不可恢复错误做无限重试。

## 4. 设计

### 4.1 错误类型

`FilterModelError` 增加 `code` 属性，允许的安全错误码：

`config`、`redirect`、`response_too_large`、`timeout`、`rate_limit`、`http_5xx`、`http_error`、`network`、`invalid_json`、`incomplete`、`model_error`。

### 4.2 请求重试

`_request_json` 拆成“单次请求”和“重试控制”两部分。仅以下错误重试：

- `timeout`；
- `rate_limit`；
- `http_5xx`；
- `network`。

最多 3 次，退避 1 秒、2 秒。配置错误、重定向、响应过大、无效 JSON 和结果不完整立即失败。

### 4.3 批次隔离

新增 `evaluate_candidates(candidates, filter_rule)`：

- 每 20 条一批；
- 某批最终失败时，把该批标记为 `semantic_decision=None`，`semantic_failed += len(batch)`，记录第一个错误码和中文安全摘要；
- 继续处理下一批；
- 返回候选列表和语义统计。

`ingest_staging_directory` 使用该函数；`semantic_failed` 只统计实际失败的批次，不再覆盖剩余全部评论。

### 4.4 可观测性

运行 `counts` 增加：

```json
{
  "semantic_failed": 20,
  "semantic_error_code": "timeout",
  "semantic_error": "智能筛选服务请求失败，请检查配置后重试。"
}
```

运行摘要显示“部分评论未能完成智能语义判断，未保存。失败类型：timeout”。运行详情显示失败数量和中文错误类型。

### 4.5 配置

`.env` 与 `.env.example` 的 `AI_FILTER_TIMEOUT_SECONDS` 默认改为 90；模型客户端仍限制在 5–90 秒。

## 5. 测试

- 重试：前两次超时、第三次成功，最终返回成功；
- 不可重试错误只调用一次；
- 批次隔离：第 2 批失败，第 1、3 批仍然被判断；
- 失败计数只包含失败批次；
- 运行摘要包含错误类型；
- 前端显示语义失败数量和中文错误类型。

## 6. 风险

- 重试会增加模型费用；仅对可恢复错误重试，最多 3 次。
- 90 秒超时会拉长单批等待时间；批次隔离保证不会因一次等待阻塞整轮剩余评论。
- 本轮仍不解决增量入库，命中结果仍要等采集结束。
