# 抖音真实地域筛选与评论者省级属地功能设计

- 日期：2026-11-14
- 状态：待用户确认
- 范围：抖音关键词任务地点筛选、视频地区结果、评论者省级 IP 属地
- 基线：从 `origin/main` 新建的 `codex/geo-comment-province`
- 工程规范：接口采用阿里云 OpenAPI 风格的资源化、版本化和统一错误约定；数据库与 Python 侧采用 `dev-standards` 中适用于本项目技术栈的命名、约束、迁移、测试和审查规则。

## 1. 背景

当前抖音任务只支持关键词、内容排序和发布时间，不能按平台地点限定搜索范围。系统还主动丢弃抖音评论公开展示的省级 IP 属地。

业务需要管理员在创建抖音任务时选择全国任意地级市或县级行政区，采集该地点内匹配关键词的视频及评论，同时查看评论者的省级 IP 属地。

## 2. 目标

- 创建和编辑抖音关键词任务时，可以选择“全国”、一个地级市或一个县级行政区。
- 每个任务只允许选择一个地点，关键词和地点必须同时满足。
- 尽可能使用抖音原生县级地点查询；只能解析到母市时，通过平台地点字段严格缩小到目标区县。
- 搜索结果只保留能够由抖音地点信息验证为目标地区的内容。
- 视频结果和导出包含平台返回的标准化省、市、区县和 POI 名称。
- 评论结果和导出包含平台公开的评论者省级 IP 属地。
- 全国模式保持现有行为，不增加地点条件。

## 3. 非目标

- 本阶段只实现抖音，不实现小红书地域筛选。
- 不支持一个任务选择多个城市或县。
- 不在界面提供省级选择。
- 不支持省级范围采集。
- 不通过关键词、标题、评论正文或作者 IP 属地猜测视频地区。
- 不采集真实 IP、经纬度、街道地址、用户精确位置或作者个人资料地点。
- 不改变现有内容排序、发布时间、评论筛选、AI 筛选和任务调度规则。
- 不在生产环境执行真实地点筛选验证或部署。

## 4. 业务术语与准确性边界

### 4.1 平台地点

“平台地点”是指抖音自身用于限定或描述视频地域的地点对象，例如城市、区县或 POI。浏览器网络出口 IP、视频标题中的城市名、作者资料中的 IP 属地都不属于平台地点。

### 4.2 严格地域验证

一个视频只有满足以下条件才是有效结果：

1. 搜索请求使用了目标地点条件，或使用了经过批准的母市降级条件。
2. 平台返回的视频地点、POI 或行政区信息能够证明视频属于目标市或目标区县。
3. 区县重名时能够通过完整层级或行政区代码消歧。

搜索接口返回候选内容不代表地域验证通过。平台返回附近地区、跨市内容或缺少地点信息的视频必须被排除。

### 4.3 可选择性不等于内容保证

系统提供全国市、县、区目录供搜索和选择，但抖音可能没有该地点的内容、没有独立地点对象，或返回内容缺少地点元数据。此时允许命中数为 0，不能把结果静默扩大到母市、全省或全国。

## 5. 已确认产品规则

- 默认地点为“全国”。
- 地点与关键词是 AND 关系：只在所选地区内搜索匹配关键词的视频。
- 全国模式不传抖音地点参数，仍使用关键词搜索。
- 每个任务只能选择一个地点。
- 用户可以选择地级市、县级市、县、市辖区，包括自治州、地区、盟和直辖市辖区。
- 省级节点只能用于结果路径分组，不能作为任务地点。
- 切换为“指定视频链接”时不使用地点条件。
- 小红书任务本阶段不显示地点选择。
- 评论者属地只显示省级或“未公开”，不得改称真实 IP。

## 6. 总体架构

系统采用四个职责明确的组件：

### 6.1 行政区目录

- 随项目发布全国行政区划快照，运行时不依赖第三方行政区接口。
- 数据包含行政区代码、标准名称、短名称、层级、父级代码、完整路径和目录版本。
- 只把地级和县级节点作为可选任务地点，省级节点仅用于分组。
- 任务保存创建时使用的目录版本，历史任务不随目录更新自动改变。
- 行政区目录来源、生成脚本、版本摘要和数据更新步骤在接口与数据库设计阶段固定。

### 6.2 抖音地点解析器

- 输入目标行政区、抖音登录态和目录版本。
- 通过抖音当前地点搜索能力解析平台地点对象。
- 使用完整路径、父级城市和地点类型消歧，不接受仅凭短名称的模糊命中。
- 区县存在唯一精确地点时返回“精确地点”。
- 区县没有精确地点但母市唯一匹配时返回“母市降级”。
- 省直辖县级行政区没有母市地点时只允许精确解析；不能回退到全省。
- 无法解析或存在同名歧义时停止任务，不猜测。
- 稳定解析结果可以缓存，缓存过期后重新验证。

### 6.3 抖音地点校验器

- 输入目标地点和平台返回的视频地点元数据。
- 输出“通过”“地区不匹配”或“地点信息缺失”。
- 市级任务要求视频地点属于目标地级行政区。
- 县级任务要求视频地点属于目标县级行政区，即使搜索使用的是母市地点。
- 只有“通过”的视频进入评论采集。
- 地点校验不读取视频标题、描述、评论正文或评论者属地。

### 6.4 抖音地域搜索适配器

- 全国模式继续调用现有搜索适配器，行为不变。
- 指定地点模式在关键词、排序和发布时间条件上增加平台地点条件。
- 抖音地点参数、签名和响应细节只存在于平台适配器，不进入任务服务或前端。
- 地点能力在隔离开发环境中通过测试账号验证，接口变化由适配器和契约测试处理。

## 7. 用户流程

### 7.1 创建抖音关键词任务

1. 用户选择抖音和“关键词搜索”。
2. 用户在“采集地点”中输入城市、区、县或县级市名称。
3. 界面显示完整路径，用户选择一个市或县；也可以保持“全国”。
4. 用户输入至少一个关键词，并设置现有排序、发布时间和数量。
5. 系统根据行政区目录在服务端重新校验地点。
6. 任务保存地点快照，默认状态不变。

### 7.2 运行任务

1. 全国任务直接执行全国关键词搜索。
2. 指定地点任务先解析抖音地点。
3. 解析失败时任务在内容搜索前失败，并显示安全的中文原因。
4. 精确地点或母市降级地点用于平台搜索。
5. 候选视频逐条执行严格地点校验；不符合目标地点的内容被排除。
6. 通过校验的视频采集评论。
7. 评论采集后继续执行现有包含词、排除词和 AI 语义筛选。
8. 入库前保存视频地点和评论者省级属地。

### 7.3 分页与数量

- 内容上限只统计通过地点校验的视频。
- 被排除的候选不占内容上限。
- 当前页没有通过校验的内容时继续翻页，直到达到上限、平台没有更多结果或触发现有安全停止条件。
- 每条有效视频的评论上限保持任务现有规则。

## 8. 地点解析决策

### 8.1 全国

- 不解析地点。
- 不增加平台地点参数。
- 不执行视频地点校验。
- 视频返回地点时仍允许展示，但地点为空不阻止入库。

### 8.2 市级任务

- 必须解析到唯一的地级地点。
- 无法解析或存在同名歧义时失败。
- 运行时要求视频地点属于目标地级行政区。

### 8.3 县级任务，存在精确地点

- 使用区县级地点查询。
- 继续使用区县级严格校验。
- 界面显示“精确地点查询”。

### 8.4 县级任务，只有母市地点

- 使用母市地点查询。
- 必须按区县严格校验。
- 地点缺失或属于母市其他区县时排除。
- 界面显示“城市内严格校验”，不能显示为精确地点查询。

### 8.5 省直辖县级行政区

- 只允许使用精确县级地点查询。
- 没有精确地点时任务失败。
- 不允许用全省地点替代。

## 9. 视频地点提取

地点信息按以下优先级读取：

1. 视频详情中的平台行政区字段。
2. 视频详情中的 POI 城市、区县和地址字段。
3. 搜索结果项中的结构化行政区或 POI 字段。

禁止使用：

- 视频标题或描述中的城市名称。
- 评论正文中的城市名称。
- 评论者 IP 属地。
- 作者资料或作者 IP 属地。
- 浏览器或服务器网络出口 IP。

通过校验的视频保存标准化省、市、区县和 POI 名称。原始平台响应不保存到数据库、日志或导出文件。

## 10. 评论者省级 IP 属地

- 一级评论和二级评论读取抖音返回的 `ip_label`。
- 只接受中国省级行政区名称。
- 保存规范短名称，例如“北京”“广东”“内蒙古”“广西”“新疆”“香港”“澳门”；带“中国”前缀的名称先去除前缀再规范化。
- 合法省级集合固定为 34 个：北京、天津、上海、重庆、河北、山西、辽宁、吉林、黑龙江、江苏、浙江、安徽、福建、江西、山东、河南、湖北、湖南、广东、海南、四川、贵州、云南、陕西、甘肃、青海、台湾、内蒙古、广西、西藏、宁夏、新疆、香港、澳门。
- 城市名、海外国家、空字符串、数字、点号、冒号和任何 IP 地址格式均为无效，保存为空。
- 不采集作者资料中的 IP 属地。
- 评论者属地与视频地区是独立维度，不能用于推断彼此。
- 结果页显示“评论者 IP 属地”，空值显示“未公开”。

## 11. 前端设计

### 11.1 创建和编辑任务

- 在平台和采集来源后显示“采集地点”。
- 只在抖音的“关键词搜索”模式显示。
- 默认值为“全国”。
- 使用可搜索、可键盘操作的虚拟化下拉列表。
- 结果按省分组，省标题不可选择。
- 每个结果展示完整路径，例如“陕西省 / 西安市 / 雁塔区”。
- 每个任务最多选择一个地点，支持清空后恢复全国。
- 切换为“指定视频链接”时隐藏地点选择并提交全国模式。
- 小红书任务不显示该控件。
- 所有新增可见文本为中文。

### 11.2 任务与运行详情

展示以下状态之一：

- “全国关键词搜索”
- “西安市 · 精确地点查询”
- “西安市 · 雁塔区内严格校验”
- “西安市 · 无法解析抖音地点，任务未开始”
- “西安市 · 抖音存在同名地点，无法安全解析”

运行统计展示：

- 候选视频数
- 地点校验通过数
- 地区不匹配排除数
- 地点信息缺失排除数
- 最终地点解析方式

### 11.3 评论结果

新增中文列和筛选：

- “视频地区”：显示省、市、区县；存在 POI 时在详情中显示。
- “评论者 IP 属地”：显示省级名称或“未公开”。

CSV/XLSX 导出增加视频地区和评论者 IP 属地。

## 12. 错误与可观测性

运行日志使用以下中文阶段：

1. 正在解析抖音采集地点
2. 正在搜索抖音视频
3. 正在校验视频地区
4. 正在采集评论
5. 正在筛选并入库评论

需要区分：

- 地点目录缺失或损坏
- 任务地点非法
- 抖音地点无法解析
- 抖音地点存在同名歧义
- 已解析地点但平台搜索失败
- 平台成功但没有任何通过严格校验的内容
- 平台内容缺少地点信息

地点查询成功但最终为 0 条时，运行状态可以成功，并明确显示“没有通过严格地区校验的内容”。地点无法解析或平台搜索失败时，运行失败且不进入评论采集。

日志和错误提示不得包含 Cookie、签名参数、请求头、完整地点原始响应或登录令牌。

## 13. 隐私与安全

- 评论者属地只保存平台公开展示的省级名称。
- 不保存真实 IP、城市、经纬度或精确位置。
- 不通过评论者属地反推身份和精确位置。
- 现有头像、签名、原始用户 ID 等禁存规则不变。
- 视频地区只用于地域筛选和聚合展示。
- 地点缓存只保存平台地点标识、标准行政区字段和验证状态。
- 真实平台验证只使用测试账号、隔离环境和隔离数据。
- 不连接生产域名、生产数据库或生产登录态。

## 14. 测试与验收方向

自动化测试覆盖：

- 全国、地级、县级、直辖市辖区和自治区行政区。
- 同名区县、非法代码、父子层级不一致。
- 县级精确解析、母市降级、无法解析和歧义。
- 按代码、完整路径匹配；短名称和缺失地点拒绝。
- 关键词与地点同时生效；全国模式行为不变。
- 内容上限只统计通过校验的视频。
- 评论者省级白名单、后缀规范化、非法值置空。
- 一级和二级评论。
- 任务编辑快照、旧任务兼容和数据库迁移。
- 结果筛选、CSV/XLSX 中文列和公式转义。
- 前端搜索、单地点选择、清空、模式切换、中文提示和移动端布局。

真实平台验证只在隔离开发环境进行：

- 使用测试账号。
- 验证一个地级市和两个县级地点。
- 包含一个重名区县场景。
- 每次最多 1 条视频、5 条评论。
- 确认平台地点条件、严格校验、排除计数和评论省级属地。
- 遇到验证码、限流或登录异常立即停止，不绕过。

## 16. 风险

| 风险 | 设计应对 |
|---|---|
| 抖音地点能力变化 | 集中在解析器和搜索适配器，通过契约测试隔离业务层 |
| 县级没有独立地点 | 仅允许母市降级并严格按区县过滤 |
| 平台返回附近内容 | 搜索范围不能代替校验，逐条验证 |
| 视频缺少地点字段 | 排除并统计，不按关键词猜测 |
| 同名区县 | 使用完整路径和行政区代码消歧 |
| 县级候选很多但通过率低 | 只统计有效内容，维持分页和请求安全边界 |
| 评论属地被误解为真实 IP | 固定文案“评论者 IP 属地”，只显示省级或“未公开” |
| 行政区目录调整 | 任务保存目录版本和地点快照 |
| 真实平台风控 | 隔离环境小范围验证，出现验证码立即停止 |

## 18. 后续设计阶段

用户确认本文档后，下一阶段只进行接口与数据库设计，不直接编码。接口和数据库设计经用户确认后，才编写实施计划并进入开发。

### 18.1 阶段门禁

1. 用户确认本功能设计。
2. 完成接口契约、数据库设计、迁移与回滚方案，并提交用户确认。

任何一步发生实质性范围或契约变化，都回到对应设计门禁重新确认。

### 18.2 接口设计交付物

- 更新项目 OpenAPI 3.1 契约，明确任务创建、编辑、查询和结果/导出中新增的地点字段。

- 给出请求/响应模型、字段类型、必填性、枚举、长度、清空和切换“全国”的语义。

- 给出稳定错误码、HTTP 状态码、中文安全提示和请求示例。
- 说明全国模式与指定地点模式的契约差异，保证全国模式行为不变。

### 18.4 规范基线

- 接口遵循项目现有 OpenAPI 3.1 契约和 HTTP 语义，参考阿里云 OpenAPI 的资源化、稳定状态码、统一错误和向后兼容原则。
- 数据库与 Python 代码参考阿里云 P3C 的通用工程原则，并按 Python/FastAPI/SQLAlchemy/PostgreSQL 技术栈适配；不机械照搬 Java 专项规则。
- 迁移使用 Alembic，所有约束、索引和回滚行为必须在设计阶段说明依据。
- 前端新增可见文本全部使用中文；接口字段、数据字典和实现使用同一英文标识与中文展示名。
- 接口或数据库设计必须通过项目开发规范中的设计门禁，不接受先编码后补契约。
