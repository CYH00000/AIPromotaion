# 任务级内容排序与发布时间筛选设计规格

- 日期：2026-11-11
- 状态：已确认；待实施
- 范围：关键词搜索任务的内容排序与发布时间范围

## 1. 目标

允许每个任务在关键词搜索时独立选择：

- 内容排序：综合、最新发布、最多点赞；
- 发布时间：不限、一天内、一周内、半年内。

抖音使用原生搜索参数；小红书使用原生排序，并在获取笔记详情后按发布时间过滤。

## 2. 非目标

- 指定链接/ID 模式按用户提供的链接采集，不应用排序和发布时间过滤；
- 不实现“按评论时间筛选”；
- 不改变评论关键词/AI 筛选逻辑；
- 不引入多任务并行。

## 3. 数据与契约

`collector_tasks` 增加：

| 字段 | 类型 | 取值 |
|---|---|---|
| `content_sort` | String(16) | `general`、`latest`、`most_liked` |
| `publish_time_days` | Integer | `0`、`1`、`7`、`180` |

`TaskCreate`、`TaskPatch`、`TaskView`、运行配置快照和 `CrawlerStartRequest` 同步增加这两个字段。

## 4. 平台实现

### 抖音

- 映射排序：`general → GENERAL`、`latest → LATEST`、`most_liked → MOST_LIKE`；
- 发布时间映射：`0 → UNLIMITED`、`1 → ONE_DAY`、`7 → ONE_WEEK`、`180 → SIX_MONTH`；
- 两个参数都传给 `search_info_by_keyword`。

### 小红书

- 排序映射：`general → GENERAL`、`latest → LATEST`、`most_liked → MOST_POPULAR`；
- 搜索 API 没有发布时间范围参数，因此在获取笔记详情后，用笔记 `time`（发布时间）与 `now - publish_time_days * 86400` 比较；
- 超出时间窗口的笔记跳过评论抓取；继续翻页寻找窗口内的内容；
- 详情模式不应用该过滤。

## 5. 界面

任务表单在「关键词搜索」模式下显示：

- 内容排序：综合排序 / 最新发布 / 最多点赞；
- 发布时间：不限时间 / 一天内 / 一周内 / 半年内。

「指定链接/ID」模式下隐藏这两个选项，并显示“按你提供的链接采集，排序和时间筛选不生效”。任务列表展示当前排序和时间范围。

## 6. 测试

- 任务契约接受合法取值、拒绝非法取值；
- 子进程命令包含 `--content_sort` 和 `--publish_time_days`；
- 时间窗口判断：2 天前在 7 天内，10 天前不在 7 天内；
- 现有任务默认 `general` / `0`，保持原行为；
- 前端构建通过。

## 7. 风险

- 小红书时间过滤发生在详情获取之后，会消耗详情请求，但不会为过期笔记抓评论；
- 平台搜索排序不保证严格时间顺序，严格“一周内”以发布时间过滤为准；
- 抖音平台参数变化时，排序/时间过滤可能失效，需要按实际接口调整。
