# 后续计划与未实现能力

- 更新日期：2026-11-11
- 状态：规划中，未实现
- 用途：记录当前版本之外的功能、优先级和验收方向；具体实施前仍需单独写规格与计划。

| 优先级 | 项目 | 目标 |

| P0 | 真实平台端到端验收 | 用小范围任务验证搜索、内容详情、评论入库、排序和时间范围 |
| P1 | 服务日志管理页 | 持久化服务日志，支持查询、筛选、下载和实时查看 |
| P1 | 按平台并行 | 抖音和小红书各一个 Worker 槽位，平台内串行 |
| P1 | 边采集边入库 | 运行中增量写入命中评论，不必等整轮结束 |
| P2 | 运行记录列表 | 查看同一任务的全部历史运行，而不只最近一条 |
| P2 | 评论快照差异浏览 | 查看点赞、回复数和作者字段随时间的变化 |
| P2 | 同任务排队合并 | 运行中再次到期时只保留一个待执行项 |
| P2 | AI 筛选提速 | 降低单批推理时间或使用更快的分类模型 |

## 1. 服务日志管理页（P1）

### 现状

- 采集器日志保存在 `crawler_manager` 的内存环形缓冲，服务重启后丢失；
- Worker、调度器、账号服务和 API 异常多数使用 `print()` 或 uvicorn 控制台，没有文件和查询接口；
- 当前只能查看最近一次运行的采集器日志，无法查看完整服务日志。

### 计划

1. 统一 Python logging 配置，写入 `data/logs/service.log`，按大小轮转并保留有限份数；
2. 接管 uvicorn、Worker、调度器、账号服务、AI 筛选错误和关键 API 异常；
3. 新增受管理员认证的接口：
   - `GET /api/logs/service?level=&q=&limit=&offset=`；
   - `GET /api/logs/service/download`；
   - 可选 `WS /api/ws/logs/service` 实时 tail；
4. 工作台新增「系统日志」标签页：级别/来源/关键词筛选、暂停刷新、下载；
5. 日志脱敏：禁止 Cookie、Token、模型 Key、完整请求头进入日志；
6. 明确保留周期和轮转策略，清理操作需显式确认。

### 验收

- 服务重启后仍能查看历史日志；
- 未认证请求不能读取日志；
- 能按级别、来源和关键词筛选；
- 日志文件轮转且不会无限增长；
- 前端构建通过，界面全中文。

## 2. 按平台并行（P1）

### 现状

全局只有一个 `crawler_manager` 和一个 Worker 槽位，抖音和小红书不能同时运行。

### 计划

- 每个平台一个 `CrawlerManager` 和一个运行队列；
- 每个平台内部串行，全局最多两个平台并行；
- 登录只占用对应平台槽位；
- 增加并发上限配置，默认 2，避免机器资源峰值；
- 界面按平台展示运行状态；
- 增加平台级忙碌、取消和恢复测试。

## 3. 边采集边入库（P1）

### 现状

评论先写 JSONL 暂存，采集结束后统一执行关键词/AI 筛选和入库；运行中只能看到暂存数量。

### 计划

- 周期性 tail 新增 JSONL 行；
- 复用现有归一化、关键词过滤、AI 批次判断和幂等 upsert；
- 记录增量已读偏移，避免重复入库；
- 运行详情显示已入库/已过滤/待处理数量；
- 保持 `(platform, external_comment_id)` 和快照唯一键约束；
- 处理进程重启和部分批次失败。

## 4. 运行记录列表（P2）

- `/api/runs` 已支持按任务查询，但任务表只显示最近一条；
- 增加任务运行历史列表：时间、触发方式、状态、阶段、计数、摘要、详情入口。

## 5. 评论快照差异浏览（P2）

- 快照表已经保存每次运行的点赞数、回复数和作者字段；
- 增加评论详情页，按时间展示数值变化和作者字段变化；
- 缺失值显示为「无」，不推测数据。

## 6. 同任务排队合并（P2）

- 设计目标是运行中再次到期最多保留一个待执行项；
- 当前定时触发可能继续追加 queued 运行；
- 增加数据库层面的 pending 去重/合并测试，服务中断后的多个过期触发合并为一次。

## 7. AI 筛选提速（P2）

- 当前每批 20 条约需 24 秒，推理 token 约 1600–2100；
- 评估使用更快的分类模型、缩小批次、并发批次（受限流约束）；
- 保留超时、重试、批次隔离和错误码；
- 先在小型真实任务上比较准确率和耗时。

## 8. Cookie/二维码增强（P2）

- 支持粘贴 Cookie 登录；
- 评估把二维码内嵌到网页；
- 增加登录态有效性探测，而不只依赖配置目录存在；
- 所有凭据继续只由服务端持有，不返回前端。

## 9. 云部署与安全加固（P3）

- 生产 Compose 拆分 Web/API、Worker、PostgreSQL 和反向代理；
- HTTPS、同源部署、密钥注入、日志轮转和备份恢复演练；
- 数据库、Worker、浏览器调试端口不公开；
- 云端账号管理和真实平台验收流程。

## 10. 交付前必须补的验证

- 完整 Python 测试、`pre-commit run --all-files`、前端 lint/build；
- OpenAPI、数据字典、README 和 CHANGELOG 随实现同步；
- 真实平台小范围验收：关键词搜索、最新/一周内、指定链接、评论入库、暂停/取消；
- 小红书指定链接 `xsec_token` 流程的真机验证。

## 不在当前范围

- 多租户、多账号、商业化、规模化采集；
- 二级评论正文；
- 自动绕过验证码、限流或访问控制；
- 多 Worker 高可用和分布式租约。
