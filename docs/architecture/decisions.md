# 架构决策记录

## ADR-001：以 MediaCrawler 上游作为采集底座

- 状态：已批准
- 决策：基于 NanmiCoder/MediaCrawler SHA 68d9ef1c1da22eab75940dfd7cec259907006538 进行二次开发。
- 原因：已经包含目标平台的采集器、FastAPI API 和 React/Vite WebUI，社区规模和维护活动高于候选增强分支。
- 代价：当前上游匿名化作者 ID，应用需在受控采集边界增加最小作者字段适配；上游不提供完整业务调度。
- 许可证：采集核心 NON-COMMERCIAL LEARNING LICENSE 1.1；WebUI GPL-3.0。

## ADR-002：沿用上游 Web/API 技术边界

- 状态：已批准
- 决策：沿用 Python 3.11+、FastAPI API 与 React/Vite 前端；以当前依赖锁为起点，公网开放前进行依赖安全兼容审查。
- 原因：减少对平台能力的重复实现，保持二开范围集中在应用工作流。
- 代价：需要持续跟踪上游结构变化，并保留两类组件的许可证声明。

## ADR-003：PostgreSQL 用于本地和云端

- 状态：已批准
- 决策：本地开发和云部署使用同一个 PostgreSQL 主版本，初期基线为 18 系列。
- 原因：调度配置、运行状态、评论主记录和快照需要事务一致性；同版本减少环境差异。
- 代价：本地开发需 Docker；升级前需备份并验证迁移。

## ADR-004：单实例调度与采集 Worker

- 状态：已批准
- 决策：APScheduler 3.11 系列，单 Worker，任务全局串行；启用任务配置存放在 PostgreSQL，服务重启时恢复。
- 原因：每平台一个账号，单用户低规模，串行便于限制资源和避免重复并发。
- 代价：没有多副本高可用；横向扩展前必须引入分布式租约/领导者选举。

## ADR-005：公网单管理员身份验证

- 状态：已批准
- 决策：公网部署需要 HTTPS 和单管理员账号密码，无注册/多租户；会话使用安全 Cookie 与 CSRF 防护。
- 原因：用户明确选择公网访问并要求账号密码登录。
- 代价：密码初始化与恢复流程必须安全；TLS 和服务器防火墙由部署过程负责。

## ADR-006：规则预览后批准

- 状态：已批准
- 决策：自然语言通过配置的云模型转换为受限 JSON 规则，预览后人工批准；批准版本不可变。
- 原因：避免模型生成的条件未经确认即生效。
- 代价：模型错误要保留待处理状态；评论文本发送到用户选择的模型服务。

## ADR-007：作者字段最小化

- 状态：已批准
- 决策：只保存平台用户 ID、昵称、主页链接；仅为命中评论作者补充主页信息。
- 原因：符合用户明确指定的数据范围。
- 代价：需修改上游匿名化边界并加强日志脱敏；链接或字段无法获取时留空。

## ADR-008：双平台定时策略

- 状态：已批准
- 决策：支持固定间隔和 Cron；初始间隔下限为 60 分钟，运行重叠合并为一个待执行项；平台访问限制时暂停。
- 原因：满足自定义周期，同时控制单账号任务密度。
- 代价：提高频率前必须人工小范围验证；中断期间不补发多次任务。

## ADR-009：AI 语义筛选规则与数据边界

- 状态：已批准并实现
- 决策：使用现有 FastAPI/Pydantic/HTTPX 增加结构化规则生成，不引入大型 Agent 框架。生成结果是受限 JSON 条件；每个草稿有独立 ID、版本和父版本，批准后只读。任务只能绑定已批准规则，运行时保存规则快照。
- 推理边界：先执行本地包含/排除词筛选，再把最多 20 条评论文本组成一批发送到服务端配置的 OpenAI 兼容云模型。作者 ID、昵称、主页链接、平台 Cookie 和账号数据不发送。模型输出只接受严格校验的 JSON 分类。
- 留存与失败：数据库只保存最终命中的评论；语义服务失败的评论不入库、不视为命中，并计入运行 `semantic_failed` 数量，任务显示部分完成。评论快照记录命中的规则版本和理由。
- 密钥：`AI_FILTER_API_KEY` 只存在服务端 `.env` 或部署密钥，不进入响应、日志、前端或版本控制。
- 代价：语义判断会产生云 API 费用和请求延迟；仅对通过关键词预筛的评论按每批最多 20 条调用模型。

## ADR-010：平台账号状态以本机浏览器配置目录为准

- 状态：已批准并实现
- 决策：抖音/小红书账号管理使用 `browser_data/` 下的浏览器配置目录和登录标记，不新增 `platform_accounts` 数据库表。
- 原因：与 MediaCrawler 的 Playwright/CDP 登录机制保持一致；本地单管理员场景无需额外持久化账号元数据。
- 代价：`configured` 只是本地配置存在性，不代表登录态仍然有效；真实有效性由任务运行时检查。

## ADR-011：运行中状态采用阶段、进度和心跳

- 状态：已批准并实现
- 决策：`collector_runs` 增加 `phase`、`progress` 和 `last_activity_at`，Worker 每 3 秒根据 JSONL 增长和采集日志更新；超过 180 秒没有活动显示「无活动」，不自动终止。
- 原因：只记录 running/终态会让用户无法区分采集中、AI 筛选中和卡死。
- 代价：运行期间增加少量数据库写入；暂存文件或日志频率低时活动时间可能滞后。

## ADR-012：AI 筛选重试与批次隔离

- 状态：已批准并实现
- 决策：超时、429、5xx 和网络错误最多重试 3 次；单批最终失败只统计该批，后续批次继续；运行计数记录安全错误码。
- 原因：推理模型单批约 20–30 秒，单次临时失败不应放大为整轮失败。
- 代价：重试会增加模型费用；批次隔离意味着部分评论可能未判断，运行标记为 partial。

## ADR-013：任务级内容排序与发布时间

- 状态：已批准并实现
- 决策：关键词任务保存 `content_sort` 和 `publish_time_days`；抖音使用原生参数，小红书使用最新排序并在详情后按发布时间过滤。
- 原因：不同任务需要不同的内容新鲜度；全局配置会互相影响。
- 代价：小红书过滤发生在详情请求之后，会消耗详情请求；指定链接模式不应用排序/时间过滤。
