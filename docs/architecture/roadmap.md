# 实施路线图

## 执行原则

所有功能基于 MediaCrawler 上游 SHA 68d9ef1c1da22eab75940dfd7cec259907006538 逐步二开。每个子系统独立验收；迁移、数据边界和许可证在合并前复核。先完成本地验证，再部署云服务器。

## 后续增量

详细设计方向、优先级和验收标准见 [后续计划](backlog.md)。

- 按平台并行：抖音和小红书各自一个 Worker 槽位，平台内串行。
- 边采集边入库：运行中增量写入命中评论，而不是整轮结束后统一入库。
- 运行记录列表与评论快照差异浏览。
- 同一任务运行中再次到期的排队合并。
- Cookie 粘贴登录、二维码内嵌网页和真实登录态有效性探测。
- 云部署、HTTPS、备份恢复与真实平台端到端验收。

## 里程碑门禁

### M0：源码基底（完成）

- 上游 Git SHA 和许可证核对通过。
- 项目分支保留现有设计文档，源代码历史明确指向上游。
- Python/Node 锁文件可在 Windows 开发环境安装。

### M1：安全基础（本地 MVP 完成，云端待验收）

- 未认证请求不能读取业务接口。
- 没有公开注册入口；密码、Cookie、模型 Key 均不回显。
- PostgreSQL 数据迁移可创建、升级和备份。

### M2：采集链路（代码完成，真实平台验收待用户执行）

- JSONL fixture 可生成内容、评论、作者最小字段和每次运行快照。
- 同一平台评论 ID 重复导入不会复制主记录。
- 错误或部分失败不会丢失已提交结果。
- 关键词任务的内容排序和发布时间范围通过任务级配置传入采集器。

### M3：规则和计划任务（功能代码完成）

- 关键词 + AI 采用 AND 规则；AI 规则必须人工批准。
- 模型错误的评论不入库、不作为命中；运行记录失败数量并显示部分完成状态。
- 模型临时错误重试，单批最终失败不影响后续批次；失败类型显示为中文。
- interval/Cron 能在重启后恢复，单实例任务串行执行。
- 暂停任务只停止未来计划，手动运行仍可执行。

### M4：本地 MVP

- 网页完成任务创建、关键词筛选、搜索和 CSV/Excel 导出。
- 使用 Postgres 验证迁移、登录、任务状态和结果 API；不在自动验证中访问真实平台。
- AI 规则预览与确认已实现；模型实际调用需配置云 API 并由用户在界面操作。
- 账号管理、运行详情、暂存数量、最近活动和中文界面已实现。
- 真实平台测试由用户手动执行，受控小规模；CI 不访问真实平台。

### M5：云部署准备

- 仅 HTTPS 管理入口对公网开放。
- 数据库、采集 Worker、浏览器调试端口不公开。
- 密钥注入、备份恢复、健康检查和回滚流程完成演练。

## 范围约束

首期按 MediaCrawler 默认一级评论采集，不扩展二级评论正文；不做商业使用、自动联系、规模化抓取、多租户或多 Worker。若用户改变这些范围，先更新设计规格与对应计划。
