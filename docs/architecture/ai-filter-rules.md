# AI 语义评论筛选

## 使用流程

1. 新建任务时，输入希望找到的评论描述。
2. Agent 将描述转成规则草稿：摘要、正向语义信号、排除情形。
3. 页面展示草稿预览。草稿不会参与筛选。
4. 管理员点击“确认并应用此规则”后，规则变为只读版本。
5. 任务只能绑定已批准版本；运行创建时将规则 ID、版本、原始意图、规则 JSON 和模型名写入运行配置快照。
6. 编辑规则时创建新版本，旧版本与已创建的运行快照不变。

## 规则结构

规则只包含模型生成的可读文本，不接受 Python、SQL、正则表达式、工具调用或动态 URL：

```json
{
  "summary": "评论表达了明确的软件开发外包需求",
  "required_signals": ["评论提到实际项目需求"],
  "positive_signals": ["询问定制开发或系统开发服务", "明确表示有软件项目需要交付"],
  "negative_signals": ["招聘求职", "课程或培训咨询"]
}
```

`required_signals` 中的条件必须全部满足；`positive_signals` 至少命中一项；命中任一 `negative_signals` 则拒绝。用户可在预览阶段检查这三组条件。

模型输出必须通过 Pydantic 字段、长度和数量校验。评论判断的返回值也必须是严格 JSON，每条包含输入序号、匹配布尔值和短理由。

## 采集判断

- 先应用任务的包含/排除词；排除词优先。
- 若任务绑定已批准语义规则，仅将通过关键词预筛的评论文本分批送往模型，每批最多 20 条，每条最多发送 2000 字符。
- 请求不包含评论作者 ID、昵称、主页链接、平台 Cookie、账号或内容链接。
- 只有语义模型判为命中的评论进入业务数据库。未命中评论不入库。
- 语义调用按 20 条一批串行执行；超时、429、5xx 和网络错误最多重试 3 次，退避 1 秒、2 秒。
- 某一批最终失败时，只把该批（最多 20 条）计入 `semantic_failed` 并跳过，后续批次继续判断；不再因为一次失败放弃剩余全部评论。
- 运行计数同时记录 `semantic_error_code` 和安全摘要，界面显示中文失败类型（如请求超时、触发限流）。
- 语义失败的评论不保存、不当作命中；运行以 `partial` 状态结束，并显示安全摘要。
- 评论快照记录匹配的规则 ID、版本和理由，便于回溯。

## 云模型配置

API 进程从服务端环境读取：

```dotenv
AI_FILTER_API_BASE_URL=https://api.deepseek.com
AI_FILTER_API_KEY=<server-side secret>
AI_FILTER_MODEL=deepseek-v4-pro
AI_FILTER_TIMEOUT_SECONDS=90
```

接口只返回模型是否已配置及模型名，不返回密钥。要求 HTTPS、公共 DNS 目标、无重定向，超时限制在 5–90 秒且响应最多 256 KiB。修改 `.env` 后重启 API 服务。

## 成本与限制

开启语义筛选会对通过关键词预筛的评论产生云 API 请求和费用。任务最大评论数受现有采集上限约束；语义调用按 20 条分批串行执行。若某批模型不可用，任务会记录该批失败并继续后续批次，已成功筛选的记录仍会保留，失败批次的评论不进入结果。
